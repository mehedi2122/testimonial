# space-crud Specification

## Purpose

Define the contract by which an authenticated, email-verified user creates, lists, and removes the Spaces they own. The Space is the unit of tenancy (PRD §7); without CRUD the dashboard, inbox, embed, and settings pages have nothing to operate on.

---

## Requirements

### Requirement: The system SHALL expose three authenticated routes for Space CRUD

The system SHALL enforce this requirement.

- `GET /spaces/create` → renders the create form (Inertia `spaces/create`)
- `POST /spaces` → persists the Space and redirects to `/spaces/{slug}/created`
- `DELETE /spaces/{space}` → soft-deletes the Space

All three routes live behind `auth + verified` middleware. `{space}` is route-bound on the `slug` column (per `Space::getRouteKeyName()`).

#### Scenario: ordering

- **WHEN** the route table is inspected
- **THEN** `/spaces/create` and `POST /spaces` are registered before `/spaces/{space}/*` so the static `/create` segment is not captured by route model binding.

### Requirement: `POST /spaces` SHALL validate the request body

The system SHALL enforce this requirement.

Required keys:

- `name` — string, 2..80 chars
- `title` — string, 2..120 chars
- `subtitle` — nullable string, ≤200 chars
- `ask` — string, 5..500 chars
- `theme` — must be one of the `SpaceTheme` enum cases
- `rating_enabled` — boolean

#### Scenario: invalid payload

- **WHEN** any required key is missing, too short, or `theme` is not an enum case
- **THEN** the response is a `422` with validation errors and no row is created

### Requirement: `POST /spaces` SHALL reject creation when the owner is at their plan's `maxSpaces()` limit

The system SHALL enforce this requirement.

The check counts the owner's live (non-soft-deleted) Spaces and compares against `User::plan()->maxSpaces()`. The same boundary semantics as `SubmitTestimonialAction::checkPlanLimit` (`>=`). Plan values: Free → 3, Pro → 25.

#### Scenario: free user at cap

- **WHEN** an authenticated user on the Free plan with 3 live Spaces submits
- **THEN** the response is a `302` to `/spaces` with a session `error` flash describing the limit; no row is created.

### Requirement: The system SHALL generate a unique `slug` for every new Space

The system SHALL enforce this requirement.

The slug is built from `Str::slug($name)`. If a Space with that slug already exists (live **or** soft-deleted — the latter reserve their slug), the system appends `-{4 random chars}` and retries. After 5 failed attempts the system raises `RuntimeException`.

Soft-deleted rows reserve their slug so a future undelete never silently re-binds an existing `/spaces/{slug}` URL.

#### Scenario: name collision

- **WHEN** the owner creates two Spaces named "Roadmap"
- **THEN** the first has slug `roadmap`, the second has slug `roadmap-{4 random chars}`, both stored.

#### Scenario: soft-deleted slug is reserved

- **WHEN** the owner creates "Echo", soft-deletes it, then creates "Echo" again
- **THEN** the second Space has a slug distinct from the soft-deleted row.

### Requirement: The system SHALL populate `public_id` and seed predefined `SpaceField` rows on creation

The system SHALL enforce this requirement.

- `public_id` is auto-generated by `Space::creating` (12-char lowercase alphanumeric, non-sequential, immutable per PRD §11).
- The `Space::created` boot creates three predefined `SpaceField` rows in mode `off`: `company_name`, `social_url`, `profile_photo`.

#### Scenario: side effects on insert

- **WHEN** a Space is committed
- **THEN** `public_id` is non-empty and exactly three `SpaceField` rows exist with `mode = off`.

### Requirement: `DELETE /spaces/{space}` SHALL soft-delete the Space the authenticated user owns

The system SHALL enforce this requirement.

Soft-delete via the `SoftDeletes` trait. Non-owner Sessions return `403`. The deleted Space is excluded from subsequent `/spaces` listings.

#### Scenario: owner deletes

- **WHEN** the owner submits `DELETE /spaces/{slug}`
- **THEN** the response is a `302` to `/spaces` with a session `success` flash and the row's `deleted_at` is non-null.

#### Scenario: non-owner attempts delete

- **WHEN** an authenticated user who does not own the Space submits `DELETE /spaces/{slug}`
- **THEN** the response is `403` and the Space is unchanged.

### Requirement: `GET /spaces` SHALL list the authenticated user's live Spaces only

The system SHALL enforce this requirement.

- Live Spaces: `deleted_at IS NULL`.
- Soft-deleted Spaces: omitted.
- Returned shape per row: `{ id, name, slug, theme, rating_enabled, created_at }`.

#### Scenario: listing excludes soft-deleted rows

- **WHEN** the owner has 2 live Spaces and 1 soft-deleted Space
- **THEN** `/spaces` returns 2 rows.

### Requirement: Plan-limit messaging SHALL use the existing session-flash pattern

The system SHALL enforce this requirement.

The `error` flash text on plan-limit rejection: `"You've reached your {plan} plan limit of {limit} Spaces. Upgrade to Pro to create more."` The Inertia index page reads the flash via `usePage().props.flash` and renders it as a destructive `Alert`.

#### Scenario: flash surfaced in UI

- **WHEN** the controller redirects with `error`
- **THEN** the Inertia index page renders an `Alert` with the message above the Space grid.

### Requirement: `GET /spaces/{space}/created` SHALL show the Space's public link

The success page SHALL show the public submission URL (`/s/{public_id}`) with Copy link and View Space actions, plus the Wall of Love URL. Only the owner can open it.

#### Scenario: owner after creating a Space

- **GIVEN** the owner has just created a Space
- **WHEN** they land on `/spaces/{slug}/created`
- **THEN** `public_url` is `/s/{public_id}` and opening it returns the submission form

#### Scenario: non-owner

- **WHEN** another user requests `/spaces/{slug}/created`
- **THEN** the response is `403`

### Requirement: Public links in the app SHALL be built by the server

Pages that show a public link SHALL receive it as a prop built by `Space::publicSubmissionUrl()`, never by concatenating the slug client-side.

#### Scenario: inbox empty state

- **WHEN** the owner opens the Inbox
- **THEN** the `public_url` prop is `/s/{public_id}`
